# Tomphie Logo 与黑白主题系统设计

日期：2026-09-11
状态：用户已确认方向，待书面审阅

## 1. 目标

把用户现有的 Tomphie 手写线条 Logo 融入网站，并增加可持久化的浅色 / 深色模式。两项能力都应强化“路径、坐标、持续生长”的现有设计语言，不引入独立于页面的加载等待。

成功后的体验：

1. 访客进入首页即可看到完整 Logo 的流线描画动画。
2. 导航、首页和页尾形成克制且一致的品牌识别。
3. 黑白模式覆盖所有页面、状态与背景字，不出现局部仍为浅色的区域。
4. 首次访问跟随系统主题，手动选择在后续访问中保持。
5. 无 JavaScript、减少动态效果和窄屏场景仍可正常阅读与操作。

## 2. 明确不做

- 不制作阻挡内容、要求访客等待的全屏启动页。
- 不在每个内容区重复摆放实体 Logo。
- 不把深色模式处理为简单反色或图片滤镜。
- 不引入主题库、动画库或新的运行时依赖。
- 不更改用户 Logo 的路径造型、比例或字形关系。

## 3. Logo 素材与组件

采用用户桌面 `tomphie-logo` 文件夹内的两套 SVG 路径：

- 完整签名版：`tomphie-logo.svg`
- 紧凑图标版：`tomphie-icon.svg`

创建 `TomphieLogo.astro`，以 `variant="wordmark" | "icon"` 控制两种图形。组件直接使用原始 SVG 路径，描边改用 `currentColor`，使同一份图形自动适应浅色和深色主题，避免维护两套黑白文件。

Logo 保持纯线条，不增加底板、阴影、发光、渐变或圆形容器。

## 4. Logo 放置

### 4.1 顶部导航

用紧凑图标替换当前品牌链接中的蓝色圆点，右侧保留 `Tomphie` 文字。图标与文字共同作为返回首页的链接。

- 桌面端图标约 28px，保留完整文字。
- 手机端图标约 26px，文字仍显示，但与菜单和主题按钮共同控制间距。
- 悬停或键盘聚焦时，图标沿路径方向轻微移动，幅度不超过 2px。

### 4.2 首页首屏

在首页姓名区上方放置完整签名版 Logo，作为进入网站后最先感知到的品牌动作。Logo 与姓名左边缘对齐，不覆盖个人照片，也不和背景镂空 `TOMPHIE` 争夺主视觉。

建议宽度：

- 手机：112–136px
- 平板：144–176px
- 桌面：176–220px

Logo 动画先完成，再由姓名与介绍进入；动画不会锁定滚动。

### 4.3 页尾

页尾左侧用小型完整 Logo 替代纯文字站名，网站描述保留在其下。页尾 Logo 静态展示，不重复播放描线动画。

### 4.4 浏览器图标

用图标版 Logo 更新 `favicon.svg`。图标保持透明背景，并通过 `prefers-color-scheme` 让描边适应浏览器的浅色与深色界面。

## 5. 首屏流线描画动画

完整 Logo 的每条路径设置统一的 `pathLength="1"`，用 `stroke-dasharray` 和 `stroke-dashoffset` 从隐藏状态逐条绘制。

动画节奏：

1. 顶部长横线先出现，确定运动方向。
2. `T` 的竖线与主体连笔依次跟进。
3. `o-m-p-h-i` 的连续曲线成为最长、最平滑的一段。
4. 末端三条速度线快速收尾。
5. 全部完成后 Logo 保持静止，不循环、不呼吸闪烁。

总时长控制在约 1.25–1.55 秒，路径之间轻微重叠，使用缓入缓出的非线性节奏。姓名在约 55% 的绘制进度后开始显现，使两个动作形成一个连续开场，而不是先后等待。

实现只使用 CSS：

- 默认状态直接显示完整 Logo。
- 仅在 `prefers-reduced-motion: no-preference` 时执行描画。
- 减少动态效果时不隐藏路径，直接呈现最终图形。
- 动画不承载任何唯一信息，Logo 为装饰时使用 `aria-hidden="true"`。

## 6. 主题状态模型

主题只有两个最终状态：`light` 与 `dark`。

首次访问：

1. 如果 `localStorage` 中存在 `tomphie-theme`，使用保存值。
2. 否则读取 `prefers-color-scheme`。
3. 在正文绘制前把结果写入 `<html data-theme>`，避免浅色页面短暂闪现。

手动切换：

1. 点击导航栏主题按钮，在 `light` 和 `dark` 之间切换。
2. 把新值写入 `localStorage`。
3. 更新按钮文字、`aria-label`、`aria-pressed` 和浏览器 `theme-color`。
4. 后续页面导航和再次访问继续使用该选择。

系统主题变化只在用户尚未手动选择时自动跟随。无法使用存储时，切换仍在当前页面有效，不显示错误提示。

## 7. 色彩令牌

| 语义 | 浅色 | 深色 |
|---|---|---|
| 页面底色 | `#F4F7FA` | `#0D1015` |
| 主文字 | `#111419` | `#F3F5F7` |
| 次级文字 | `#555E68` | `#A6AFBA` |
| 分隔线 | `#D3DAE2` | `#2A3039` |
| 路径蓝 | `#1748D2` | `#7E9CFF` |
| 珍宝玫瑰 | `#9B4257` | `#D28AA0` |
| 实体表面 | `#FFFFFF` | `#151A21` |

黑白模式改变明暗关系，但保留路径蓝与珍宝玫瑰。这样可维持品牌识别，也能确保轨迹进度和交互状态清晰。

所有组件只消费语义令牌。当前路线卡片中的固定 `rgba(244, 247, 250, ...)`、移动菜单的 `bg-white` 和其他硬编码颜色需要迁移到主题令牌。

## 8. 主题按钮

主题按钮放在顶部导航最右侧：

```text
[Logo + Tomphie]       [主导航]  [主题按钮]
```

按钮采用一个由半圆和圆点构成的黑白图形，不使用带文字的大型开关。可访问名称明确写为“切换到深色模式”或“切换到浅色模式”。

交互反馈：

- 悬停：图形轻微位移，边线对比增强。
- 按下：沿用全站轻微缩放反馈。
- 切换：颜色在 180–240ms 内过渡，图标内部圆点短距离滑动。
- 键盘：原生 `button`，保留清晰焦点轮廓。
- 减少动态效果：立即切换，不做位移和颜色过渡。

移动端的主题按钮始终位于菜单按钮旁边，不藏进折叠菜单，方便随时切换。

## 9. 响应式与视觉控制

- 320、375、768、1024 和 1440px 下导航不换行、不溢出。
- 首页 Logo 在小屏缩小，不压缩姓名和身份文字。
- 深色模式下照片保持自然色彩，不使用反色或统一灰度滤镜。
- 镂空 `TOMPHIE` 的描边从现有语义色自动计算，深色模式下控制对比度，仍作为背景而非正文。
- 路线卡片、移动菜单、页尾和联系按钮都必须使用主题表面色，不能留下浅色矩形。
- 页面主题切换不触发布局位移。

## 10. 组件边界

计划创建：

- `src/components/TomphieLogo.astro`：渲染两种 Logo 和可选首屏描画状态。
- `src/components/ThemeToggle.astro`：主题按钮与客户端交互。

计划修改：

- `src/layouts/BaseLayout.astro`：首屏前主题初始化、主题色元数据。
- `src/styles/global.css`：浅色 / 深色语义令牌与过渡规则。
- `src/components/SiteHeader.astro`：导航 Logo 和主题按钮。
- `src/components/ProfileHero.astro`：首屏完整 Logo 与组合动画。
- `src/components/SiteFooter.astro`：页尾签名。
- `src/components/RouteIndex.astro`：移除固定浅色背景。
- `public/favicon.svg`：替换为主题自适应图标。

不会修改内容数据、页面文案、个人照片和各内容栏目结构。

## 11. 测试与验收

自动检查：

- Logo 两种变体均能渲染，首屏路径拥有描画属性。
- 构建产物包含主题初始化脚本、主题按钮和可访问标签。
- 所有固定浅色卡片背景被语义令牌替换。
- `npm run verify` 全部通过。

人工检查：

- 首次进入首页时 Logo 一次性流畅勾勒，不阻止滚动。
- 刷新页面不出现明显的错误主题闪烁。
- 浅色、深色和系统跟随三种进入路径结果正确。
- 手机导航同时容纳品牌、主题按钮和菜单。
- 键盘可以操作主题按钮，辅助技术可理解当前动作。
- 减少动态效果时直接显示完整 Logo。
- GitHub Pages 部署后主题偏好能跨页面保持。
