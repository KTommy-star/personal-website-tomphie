# 隐私与发布边界

## 先记住一条原则

页面没有链接、条目标记为 `private`，都不等于真正的访问控制。只要私人文字或原图进入公开 Git 仓库或最终静态构建产物，就可能被他人取得。

## 当前项目的安全默认值

- `treasure` 内容默认使用 `visibility: private`；
- 每条共同记忆必须显式记录 `consentConfirmed`；
- 未确认公开范围的文字、人物姓名、时间、地点和照片，不进入仓库；
- 不把密码、身份证明、联系方式、定位信息或原始私密媒体写入 Markdown；
- 环境变量和密钥只放在部署平台，不提交到 Git。

这些字段是内容审核护栏，不是身份验证系统。

## 两种发布方式

### 公开精选版

适合 GitHub Pages。只发布双方明确同意公开的少量内容，并对敏感信息做必要模糊化。仓库中不保存未公开原稿。

### 真实私密版

需要带服务端身份验证、授权和私有存储的平台，不能只依靠 GitHub Pages。若以后选择这一方案，应把珍宝库从公开静态站点中拆分出来，单独设计登录、数据存储、备份和撤回机制。

## 素材进入项目之前

每份珍宝库素材至少确认：

1. 双方是否同意公开；
2. 可公开到什么范围；
3. 是否需要隐藏真实姓名、日期或地点；
4. 原图是否包含定位、设备等元数据；
5. 撤回后需要删除哪些源文件和构建产物。

在发布方式尚未确定前，默认只设计界面与交互，不录入真实私人内容。
